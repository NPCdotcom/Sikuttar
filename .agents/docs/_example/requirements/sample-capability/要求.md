# 要求定義（例: sample-capability）

> **サンプル slug**: `sample-capability` は **リネーム必須**（例: `data-export`, `audit-log`）。中立な「データ出力」能力の例。

## 背景

利用者が一覧から選んだレコードをファイルとして持ち出したい。

## ステークホルダー

- 利用者（エンドユーザー）
- 運用担当（サポート）

## 要求一覧

| ID | 要求 | 優先度 |
|----|------|--------|
| R1 | 選択したレコードを一括でダウンロードできる | must |
| R2 | 出力形式は少なくとも 1 種類（例: CSV） | must |
| R3 | 全件を無制限に毎回出力できる | could（初期は out） |

## 成功のイメージ

「選ぶ → 出力 → 手元で確認」が迷わず終わる。

## エージェント提案

| 選択肢 | メリット | デメリット |
|--------|----------|------------|
| A: 同期ダウンロードのみ | 実装が単純 | 大量件でタイムアウト |
| B: 非同期ジョブ + 通知 | 大量件に強い | インフラ増 |

**推奨**: 初期は A（件数上限付き）→ 必要なら B へ（H2 で再設計）
