失敗談共有 × 集合知

NPC · rako · hiroto

一行でいうと

愚痴感覚で失敗談を投稿し、
他人のしくじりから学べる Web アプリ。

ダメ出しされない設計の、学習向け SNS 的プロダクト。

なぜ作るか

失敗無き学習は、失敗を防ぐことに寄与しない。
  • 自分の失敗だけが学びの源になりがち
  • 他人のしくじりこそ先回りの財産
  • だから「書いてよい」「見つかる」場が要る

普通の SNS / Q&A と違うところ

  • ダメ出ししない — 自由コメントなし。わかる / 参考になる だけ
  • 晒さない — フィードは匿名。BAD 件数は出さない
  • 学びを取り出す — 検索と質問で集合知を手元に戻す

できること

  • 投稿（本文必須 · 状況/原因は任意）
  • フィード · 詳細 · わかる / 参考になる
  • 意味検索（Vectorize · 失敗時 Jaccard）
  • 質問（テンプレ応答 + 根拠リンク · 生成 LLM なし）
  • タグ · ブックマーク · ダッシュボード · 自分の投稿削除

  2. 検索「本番公開の直前チェックを怠った話」→ 言い換えでも近い投稿

     └─ Vectorize（sikuttar-stories）

チャット生成は載せない。Retriever が先。

見どころ 1 — 心理安全性

  • わかる（全体類似）と 参考になる（学び）を分離
  • 自由記述コメントを置かない
  • BAD は内部用 · 公開件数なし

「書いてよい」を機能ではなくルールで支える。

見どころ 2 — Retriever を段階で強くする

  • A — 無料で計測 · 長文 floor · 評価セット
  • B — Vectorize で言い換え対応 · 弱ヒットは閾値で切る
  • C — 生成 LLM（未搭載 · 必要なら後段）

測ってから載せる。B のとき C は同時に開かない。

費用とクオリティ

  • 質問の応答はテンプレ（Neuron をチャットに使わない）
  • 埋め込み検索だけを本番オン
  • 障害時は Jaccard にフォールバック

「RAG = Retriever が先、Generator は任意」をそのまま実装方針にした。
