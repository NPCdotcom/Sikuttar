# 要求定義 — 失敗談共有（failure-share）

## 背景

愚痴感覚で失敗談を共有し、他人の失敗から学びたい——共同開発などで「失敗が許容される」場が欲しい、という動機（charter §2）。  
差別化の芯は失敗談を中心に集積し、集合知を強めること（charter §9）。  
発表期限は約 2 週間（Assumption）。MVP は投稿・閲覧が動くこと。

## ステークホルダー / 利用者

| 関係者 | 主な関心 | 優先 |
|--------|----------|------|
| 開発者（初期利用者） | 失敗談を書き、他者の失敗談を読む | 高 |
| 共同開発者（NPC, rako） | ドキュメントと実装の同期・発表可能な骨格 | 高 |
| 将来の職種横断利用者 | 失敗共有・学習（当面スコープ外） | 低 |
| 非利用者 | 荒らし・糾弾・情報悪用を主目的とする者 | 対象外 |

## 要求一覧

| ID | 要求 | 優先度 | charter |
|----|------|--------|---------|
| R1 | ブラウザだけで、愚痴感覚の失敗談を投稿できる | must | §4–5 MVP |
| R2 | 投稿した失敗談を、タイムライン／フィードとして閲覧できる | must | §5 MVP |
| R3 | 状況・原因などの詳細は任意入力でよい（必須にしない） | must | §4 |
| R4 | 表示上は匿名性を保てる（身元晒し・実名必須にしない） | must | §4 |
| R5 | 限定リアクション「わかる」「参考になる」で共感／有用さを分けて示せる | should | §4 · 着手順 2 |
| R6 | ダメ出し・糾弾・論破が主用途にならない体験ガードがある（自由記述の批判コメント中心にしない） | should | §4 · §6 |
| R7 | BAD 系シグナルは公開数値・公開ランキングに出さない（システム内部参考に留める） | should | §3–4 |
| R8 | 反応が少ない／古い投稿の露出を抑えるなど、表示優先度の枠組みで集合知の質を守れる | could | §3 · 着手順 4 |
| R9 | 蓄積した失敗談から、関連する他人の失敗が提示される（類似提示／RAG 段階） | could | §5 · 着手順 3 |
| R10 | アカウント属性（職業等）は内部で持てるが、初期は表示しない | should | §4 |
| R11 | 拡張しやすい骨格（継ぎはぎだけの発表回避）として残る | should | §6–7 |

優先度の読み方: **must** = MVP（投稿・閲覧の一続き）。**should** = MVP 直後〜発表までに寄せたい。**could** = 余裕があれば／後段。

## 成功のイメージ（非技術）

- 開発者が失敗を短く投稿し、すぐ一覧で読める。
- 「ダメ出しされない」と感じられる範囲で、わかる／参考になるだけが反応の軸になる。
- 発表時点で少なくとも投稿→閲覧が動く。類似提示や表示優先度は骨格を壊さない範囲で足せる。

## 非要求（やらないこと · charter 非目的の転記）

- 糾弾・論破・成功自慢中心の SNS 化
- BAD 数やいいね至上の公開評価競争
- 実名必須の失敗告白
- 職種横断の本格展開（当面）

## 認識オブジェクト（名前だけ · H1 以降で展開）

- 失敗談（投稿）
- フィード／タイムライン
- 限定リアクション（わかる / 参考になる）
- BAD シグナル（非表示・システム用）
- 表示優先度
- 関連失敗の提示（RAG · 後段）
- アカウント属性（内部） / 匿名表示

## エージェント提案（選択肢・推奨）

| 選択肢 | 内容 | メリット | デメリット |
|--------|------|----------|------------|
| A | 本ドキュメントの must を R1–R4 に固定し、R5–R7 を発表目標 should | MVP が明確で間に合いやすい | リアクション無しだと差別化が弱い |
| B | R1–R7 までを must に引き上げる | 体験ガードが最初から揃う | 2 週間リスクが高い |
| C | R1–R2 のみ must、他はすべて could | 最短で動く | charter の体験方針が後回しになりすぎる |

**推奨: A** — charter の MVP 定義（投稿・閲覧）と着手順に一致。R5–R7 は should として同じ要求セットに残す。

**決定（2026-10-15）**: ユーザー「要求 agreed」→ 推奨 A・slug `failure-share`・用語 alignment を含む合意。
