# Capability — 秘書型 AI Q&A（審議）

親: [charter](charter.md) §8（関数追加で拡張 · 並行 SNS 分類は立てない）。  
参考: [講義 Cloudflare RAG](../../references/lecture-alterbooth-cloudflare-rag.md)（非方針）。  
wave2 本線（投稿 · 類似／意味検索 · タグ · ブックマーク · OAuth）は **維持**。本波は **秘書面の追加**。

**agreed 2026-10-18**（関連候補パラメータ · Open 1–7 推奨一式）。  
文書化: [secretary-inquiry](../elements/secretary-inquiry.md) · [要求-secretary](../../requirements/failure-share/要求-secretary.md) · [要件-secretary](../../requirements/failure-share/要件-secretary.md) · [ADR 0002](../../adr/0002-secretary-qa-template-response.md)。実装は次波。

## ユーザー方針（合意 · 2026-10-18）

| 項目 | 方針 |
|------|------|
| 位置づけ | 既存の投稿＆類似検索に **加えて** AI Q&A 秘書を組み込む（完全な路線変更ではない） |
| 技術動機 | 生成付き Q&A ·（将来）R2 取込 · AI Search は高度技術として優越性の参考。ただし **課金を膨らませない** |
| 入り口 | **自由質問** → 専用タブ。**投稿起点** → 詳細等のアクション（例: 質問に追加）で秘書入力へ載せる |
| 根拠の見せ方 | 失敗談コーパス · 自分のブックマーク · タグを文中で役割が分かるように分ける |
| 属性 | 公開 JSON には出さない（FR13 維持）。秘書応答でのみ、**個人特定にならない集計**として使う |
| 属性の母数 | **フォーカス中の投稿集合の 1/3 以上**（比率）。ユーザー表記「3/1」＝三分の一 |
| フォーカス中 | 質問の話題に**意味的に関連する**投稿群。全コーパス無差別ではない |
| 投稿起点 | 起点投稿をフォーカスへ **強制インクルードしない** |
| 関連候補 | 上限 **20** · Jaccard **score > 0** · Vectorize topK のみ · 根拠リンク **3〜5** |
| 属性集計キー | **occupation のみ**（v1） |
| 1/3 未満 | **属性節を省略**（他節は出す） |
| 認識単位 | **E12 · 秘書照会** |
| API / フラグ | **`POST /assistant/ask`** · **`SECRETARY_QA=off\|on`**（既定 off） |
| 受け入れ | **ローカル Pass（方針 B）** · CF デプロイ / Paid は別ゲート |
| AI Search / R2 | **CF 初回公開 + Paid 明示 Go のあと**再評価 |
| ブックマーク根拠 | 採用（**本人の一覧にのみ**載せる） |
| 出力 | 短い助言 ＋ 根拠リンク。根拠不足なら答えない／確認できない |
| 応答組み立て | **テンプレのみ**（v1 · LLM なし · ADR 0002）。根拠無しなら答えない |
| スタック初手 | 既存意味検索経路の再利用 |
| 個人プロフィール面 | **必要**（秘書とは別）。軽いプロフィール · 自分の投稿 · ブックマーク（X プロフィール欄に近い） |

### 応答テンプレ例（秘書文）

> このような失敗は、[属性帯]の人に良く見られるみたいです。原因としては[原因]があります。解決の例は[解決の例]などがあります。これは、あなたのブックマークの[投稿]にも類似しています。[タグ]のようなタグが関連性が強いです。

（属性帯は母数条件を満たすときのみ。満たさないときは属性節を省略。）

## 合意詳細（旧 Open 1–7 · 2026-10-18）

### 1. 認識単位・要素 ID — **E12 · 秘書照会**

一文: 蓄積失敗談に基づき短い助言と根拠を返す照会。E9 は一覧提示のまま残す。

### 2. 属性キー — **occupation のみ（v1）**

`attributes_json` は語彙固定後に拡張可。

### 3. 1/3 未満 — **属性節を黙って省略**

原因・解決・ブックマーク・タグ節は通常どおり。全体を「確認できません」にはしない（根拠がある場合）。

### 4. API / フラグ

- **`POST /assistant/ask`**  
  body: `{ "question": string, "seed_story_id"?: string }`  
  → `{ answer, evidence[], attribute_hint? }`
- **`SECRETARY_QA=off|on`**（既定 **off**）。on でも根拠 0 なら助言なし。応答はテンプレ（ADR 0002）

### 5. プロトタイプ受け入れ — **ローカル Pass（方針 B）**

Jaccard · フラグ on · **テンプレ応答**。属性 1/3・省略ルールをデモ。CF デプロイ / Paid は別ゲート。

### 6. AI Search / R2 — **後段ゲート**

秘書 MVP（既存検索経路）の価値確認後、かつ **CF 初回公開 / Paid の明示 Go** が揃ってから再評価。

### 7. 個人プロフィール面（秘書とは別 · 同日合意）

| 項目 | 合意 |
|------|------|
| 画面名 | **プロフィール** |
| 範囲 | 軽いプロフィール（内部属性）· 自分の投稿 · ブックマーク |
| API | **`GET /me/stories`**（要追加） |
| 秘書入口 | **専用タブが主**。プロフィールへの常設は不要 |
| 載せない | 秘書履歴 · 公開身元 · フォロー/フォロワー |

## 関連候補の上限・スコア（合意 · Fact）

| 項目 | 値 |
|------|------|
| 上限 | **20** |
| Jaccard | **score > 0** の上位 20 |
| Vectorize | topK=20 のみ（追加カットなし） |
| 根拠リンク | 本文に **最大 3〜5** |

既存目安: `searchStories` limit=20 · `findRelatedStories` は詳細カード用（上位 3）で秘書フォーカスとは別。

運用チューニング（閾値引き上げ等）は実装後データで可。

## 課金を膨らませない工夫（合意設計）

1. 既定経路: 既存 `searchStories` / 類似因子
2. 根拠不足 → 助言なし（生成呼び出しもなし）
3. **v1 応答はテンプレのみ**（ADR 0002 · チャット生成 LLM なし）
4. AI Search / R2 は初手必須にしない
5. 属性集計は D1 の粗い COUNT。母数未満は属性なし
6. `SECRETARY_QA` で秘書経路を隔離
